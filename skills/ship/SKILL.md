# /ship — Ship It

Unified workflow: test, review, commit, push, PR. Non-interactive by default — run straight through. Only stop for test failures, merge conflicts, or review findings that need judgment.

**Usage:**
- `/ship` — full workflow
- `/ship quick` — skip review, just test + commit + push + PR

---

## Step 1: Pre-flight

1. Check current branch. If on main, abort: "Ship from a feature branch."
2. `git status` — include any uncommitted changes.
3. Detect base branch: check `gh pr view --json baseRefName` first, then `gh repo view --json defaultBranchRef`, fallback to `main`.
4. `git diff <base>...HEAD --stat` and `git log <base>..HEAD --oneline` to understand what's being shipped.

---

## Step 2: Sync Base

Fetch and merge the base branch so tests run against merged state:

```
git fetch origin <base> && git merge origin/<base> --no-edit
```

If merge conflicts: try auto-resolving simple ones. If complex, STOP and show.

---

## Step 3: Run Tests

Detect the project's test framework and run it:
- `package.json` with a test script → `npm test` or `bun test`
- `Gemfile` → `bundle exec rails test` or `bundle exec rspec`
- `pytest.ini` / `pyproject.toml` → `pytest`
- `go.mod` → `go test ./...`

If no test framework detected, skip with note: "No test framework found — skipping tests."

**If any test fails: STOP. Do not proceed.**

If all pass: note counts briefly and continue.

---

## Step 4: Pre-Landing Review (skip if `quick`)

Launch a review subagent against the diff. It checks:
1. No debug artifacts (console.log, debugger, TODO, FIXME)
2. No commented-out code
3. No lint disables (eslint-disable, @ts-ignore)
4. No secrets (API keys, tokens, passwords)
5. No silently swallowed errors (empty catch blocks)
6. No N+1 queries (DB calls in loops)

Classify findings:
- **AUTO-FIX:** obvious issues (dead console.log, unused imports) — fix silently
- **ASK:** judgment calls — present to user

If fixes were applied, re-run tests before continuing.

---

## Step 5: Commit

Analyze the diff and create bisectable commits:

1. Group changes into logical units (one logical change = one commit, not one file = one commit).
2. Order: infrastructure first → models/services → controllers/views → config.
3. Each commit independently valid — no broken imports.
4. Message format: `<type>: <summary>` (feat/fix/chore/refactor/docs).
5. Only the final commit gets the co-author trailer.

If the total diff is small (<50 lines across <4 files), a single commit is fine.

---

## Step 6: Push + PR

```
git push -u origin <branch>
gh pr create --base <base> --title "<type>: <summary>" --body "<auto-generated>"
```

PR body includes:
- Summary (bullet points from commits)
- Test results (pass counts)
- Review findings (if any)

**Output the PR URL.**

---

## Verification Gate

IRON LAW: if any code changed after Step 3 (from review fixes), re-run tests before pushing. "Should work" is not evidence — see `/verify`.

---

## Rules

- Never skip tests (unless no framework exists).
- Never force push.
- Never ask for trivial confirmations ("ready to push?", "create PR?").
- If tests fail, stop. Do not proceed.
- The goal: user says `/ship`, next thing they see is the PR URL.
